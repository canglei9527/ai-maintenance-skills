# 评估提示

以下提示只用于在支持 Skills 的 AI 客户端中进行人工评估，不是终端用户每次使用时必须复制的提示词。正常安装后，用户直接用自然语言描述任务即可；评估提示用于验证 Skill 是否能自动触发、是否遵循边界和是否正确收尾。

## 1. 未知目标的 Bug

```text
请修复一个 Bug：搜索“斗罗大陆”后切换到“小说”筛选页，漫画来源也显示出来了。预期漫画只出现在“漫画”或“全部”页。请先搜索定位文件和函数，只读取目标函数、直接依赖和最小测试；修复后运行最小验证并记录根因。
```

期望触发 `ai-project-maintainer`，先确认项目根和目标锚点，读取 `AGENTS.md`/`ai-context` 索引，再定位筛选逻辑；只读取直接一跳数据边界和测试，不扫描整个仓库。

## 2. 已知函数的回归

```text
执行函数级 Bug 修复。文件 `src/order.py` 的 `calculate_total` 在折扣为空时抛出 TypeError；预期没有折扣时返回原价。请保留函数签名，只读取直接依赖和最小测试，补回归测试，运行 `pytest tests/test_order.py`，并记录根因、修改和验证结果。
```

期望 Skill 保留签名，增加针对空折扣的行为测试，并如实报告命令结果。

## 3. 从零创建项目

```text
从零创建一个 Python + Flask 的书源搜索服务，支持搜索、按类型筛选和健康检查。请先输出目录结构、模块职责、接口和调用关系，再创建代码。配置集中管理，每个关键功能有最小测试，并生成 AGENTS.md、ARCHITECTURE.md、BUG_HISTORY.md 和中文提问模板。完成后运行语法检查、测试和启动验证。
```

期望触发 `ai-project-bootstrapper`，先选择或创建独立项目根目录，把源码、测试、配置和文档都放进该目录；先设计边界，不把所有功能塞进一个文件，并报告未验证的外部依赖或环境限制。

## 4. 导入已有项目但未同意整理

```text
我刚把一个旧的 Python 项目导入当前工作区，文件都散在根目录。先帮我看看怎么维护，不要现在移动文件。
```

期望触发 `ai-project-maintainer` 的导入检查场景：只做浅层项目地图，说明整理会改变文件路径，并先询问是否整理；在用户同意前不得移动或重命名文件。

## 5. 同意整理导入项目

```text
同意整理这个已导入的 Python 项目。请先运行现有测试建立基线，再给出迁移表，把源码、测试、配置和文档按职责整理，保留兼容入口，整理后重新运行同一套测试和启动检查。
```

期望先报告目标结构和风险，再建立基线，分批整理，更新引用，比较整理前后结果，并记录架构变化。

## 6. 整理后验证失败

```text
整理后测试失败了。请不要继续扩大重构，区分这是整理前就存在的失败还是整理引入的回归；如果是回归，请恢复失败批次并报告恢复结果。
```

期望停止继续移动，比较基线和后测，必要时恢复失败批次，不声称整理完成。
## 7. 独立程序需求的分流

```text
智能根据渠道状态选择 GLM 的分组：发现错误时切换到没有错误的 GPT 分组，倍率越低越优先，后台实时监测并自动恢复。我要一个 Windows 常驻的后台路由程序，先设计结构再创建代码。
```

期望直接触发 `ai-project-bootstrapper`，先确认独立项目根目录和父工作区边界，创建根 `AGENTS.md` 与 `ai-context/` 索引，再创建独立项目目录；不应先触发 `ai-project-maintainer`、扫描当前工作区或启动查找现有分组逻辑的子代理。

## 8. 现有项目证据的维护分流

```text
在现有项目 `src/router/group_selector.py` 的 `select_group` 函数中增加 GLM 渠道错误切换逻辑，修复后运行 `tests/test_group_selector.py`。
```

期望触发 `ai-project-maintainer`，只读取目标函数、直接一跳的项目自有依赖和最小测试。
