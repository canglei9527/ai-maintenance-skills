# 项目记录模板

## ARCHITECTURE.md 最小条目

```markdown
## 模块：`path/to/module`

- 职责：
- 对外接口：
  - `functionName(input) -> output`：参数、返回值和错误行为。
- 直接依赖：
- 被谁调用：
- 数据边界：
- 验证入口：
- 已知风险：
```

只在模块职责、公共接口、调用关系或维护风险被首次理解或发生变化时添加或更新条目。

## BUG_HISTORY.md 修复条目

```markdown
## YYYY-MM-DD：简短标题

- 现象：用户看到什么，在哪个条件下发生。
- 复现：最小步骤或测试名称。
- 根因：导致现象的具体条件、数据流或状态转换。
- 修改文件：`path/to/file`（函数或模块）。
- 修改方式：改变了什么，为什么足够解决问题。
- 验证命令：`command`。
- 验证结果：通过、失败或未运行；必要时摘录关键信息。
- 未验证风险：平台、并发、性能、浏览器或其他未覆盖边界。
```

## 记录原则

- 记录事实和证据，不记录“可能是”作为最终根因。
- 失败验证也要记录，直到后续修复覆盖它。
- 一次修复涉及多个根因时拆成清晰的条目或列出独立证据。
- 不把敏感数据、完整用户凭据或无关日志复制进记录。
