# v0.4.5 发布介绍：输出预算闸门，降低 AI 上下文膨胀

发布日期：2026-08-24 · 版本线：0.4.4 → 0.4.5

## 一、这次发布解决什么问题

在维护已有项目时，单个源码文件可能并不大，但 AI 会连续执行搜索、读取、命令、差异和远程查询。原有规则限制了“读多少个文件”，却没有限制“每次返回多少内容”以及“整个任务累计返回多少内容”。

因此会出现一种容易误判的情况：每一步都只读了一个小文件，最后上下文却因为多个正常操作的输出叠加而迅速膨胀。`v0.4.5` 为这条链路增加可执行的字节级预算。

## 二、具体改动

### 1. 主 Skill 增加输出预算门

`skills/ai-project-maintainer/SKILL.md` 现在明确要求：

- 单次读取默认不超过 150 行 / 15 KB。
- 单次命令输出默认不超过 8 KB。
- 单个任务累计工具输出达到约 40 KB 时，先总结当前证据和下一步边界，再决定是否继续。
- 大型或脏仓库优先使用 `git diff --stat`，不要无边界地载入完整工作树差异。

### 2. 快速路径增加具体处理规则

`references/fast-path.md` 新增“输出预算”章节，覆盖：

- Read、命令和搜索结果的单次成本。
- 达到累计预算后的暂停和总结动作。
- `git diff --stat` / `git diff --shortstat` 的使用边界。
- Web 搜索或 WebFetch 的 HTML/JSON 片段上限。
- `.gz`、`.zip`、`.tar`、图片、PDF、二进制等文件的专用读取方式。

### 3. 保留原有导航规则

本版本没有删除原有的 50 个搜索命中、12 个候选文件和一跳依赖限制。新增预算是对输出成本的补充约束，不会把普通维护任务自动变成全量扫描，也不会要求 AI 为每个小任务创建额外项目文档。

## 三、对使用者的实际影响

- 读取很多小文件时，AI 会更早汇总已知事实，减少重复把原文带回上下文。
- 查看脏仓库时，默认先看变更统计，再按目标路径读取有限 diff。
- 需要完整日志、完整差异或更大文件片段时，必须有明确理由并分段读取。
- 远程响应和压缩文件不再默认以原始内容形式进入上下文。

这些规则只改变 AI 的调查和读取方式，不改变项目源代码、运行时接口、安装命令或 Skill 的四条维护路径。

## 五、安装与使用

```bash
npx skills add https://github.com/canglei9527/ai-maintenance-skills
```

安装后直接用自然语言描述维护任务即可。对于当前已安装的 Skill，需要重新同步或重新安装后才会获得 `v0.4.5` 的预算规则。
