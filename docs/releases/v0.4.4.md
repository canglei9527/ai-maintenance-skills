# v0.4.4 发布介绍：触发式索引维护与按规模输出报告

发布日期：2026-08-16 · 版本线：0.4.3 → 0.4.4

## 一、这次发布解决什么问题

前一版规则把长期维护所需的 DURABLE 形态、索引记录和完整报告过早应用到所有任务。结果是简单问答或单文件修复也可能创建不必要的 `ai-context/INDEX.md`，输出一套与任务规模不匹配的长报告；结构债务提示也可能打断本应继续完成的聚焦修复。

## 二、具体改动

### 1. 索引维护改为触发条件制

只有在本次任务新增文件、目录、公共入口或稳定任务路由，且项目确实需要导航，或者完成 `STRUCTURAL_CHANGE` 时，才更新或新建 `ai-context/INDEX.md`。

`READ_ONLY`、单文件 Bug 修复、仅改实现细节和 `MICRO` 单文件脚本不再因为默认维护等级被迫创建索引。

### 2. 完成报告按任务规模分级

- 简单单文件问答直接给出结论。
- 1–2 文件的小改动内联列出修改和验证。
- 复杂变更和结构迁移继续使用完整的路径、授权、验证、结构状态和风险报告。

### 3. 结构债务提示改为非阻断附注

命中 `ACCUMULATING_STRUCTURAL_DEBT` 时，聚焦修复仍然可以完成请求的行为；维护者在完成报告的“未完成与风险”字段中记录触发信号和候选所有者。只有用户明确要求解决结构问题时，才进入 `STRUCTURAL_CHANGE`。

### 4. Bootstrapper 默认档位调整为 STANDARD

不确定时使用更适合普通 CLI、Web 应用、服务和自动化工具的 `STANDARD`。只有长期 AI 维护、多人协作、多入口、多工作流或安全、硬件、财务、数据一致性等高风险约束，才使用 `DURABLE`。

## 三、兼容性与边界

- 保留结构迁移的授权、责任迁移表、旧实现删除证明和验证门。
- 不因为文件行数本身强制重构，也不把索引当作逐文件读取清单。
- 本版本减少不必要的上下文和文档输出，但没有降低结构变更的证据标准。

## 四、验证结果

`v0.4.4` 的变更已通过仓库验证和 Node 回归测试；GitHub Release 记录了索引维护、报告分级、结构债务附注和 STANDARD 默认档位四项变化。
