# v0.4.8 发布介绍：收紧 Bug 修复的执行范围

发布日期：2026-08-26 · 版本线：0.4.7 → 0.4.8

## 一、这次发布解决什么问题

连续 Bug 修复任务可能因为读取过多大文件、跨模块宽搜、重复比较未跟踪文件和无边界重跑构建而迅速扩大上下文消耗。本版本把这些经验转成维护 Skill 的执行约束，让普通修复保持在一个可验证的局部阶段。

## 二、具体改动

### 1. 单阶段执行

每次维护请求先记录一个当前目标、一个文件组和一个首要验收标准。后续 backlog 不自动并入当前阶段；在线下载、分页、Web、数据库、打包和设备回归等独立工作必须分阶段完成。

### 2. 局部读取和搜索

普通 Bug 修复每轮最多读取 2–3 个文件，并优先读取目标方法、调用点或报错附近的局部行。搜索限定到单文件、单模块或单个符号，默认排除大型数据、生成物和无关模块。未跟踪大文件不再使用完整 `git diff --no-index`。

### 3. focused test 和失败诊断

发现首个可验证根因后先运行 focused test，再修改和重新验证。构建失败时先读取报错位置前后约 40 行，确认文件时间、Git 状态和工具调用之间是否发生并发修改；没有新证据或新假设时不重复全量编译。

### 4. 代理和完成状态

默认不启动并行代理。必要时只允许一个有界代理，并设置无进展、超范围和跨层架构需求的停止条件。报告区分 `VERIFIED_COMPLETE`、`MODIFIED_UNVERIFIED`、`DESIGN_OR_PARTIAL`、`NOT_STARTED` 和 `BLOCKED`，只有有实际验证证据的部分才能写成完成。

## 三、兼容性与边界

这些规则只约束 AI 的维护执行方式，不改变项目源代码、运行时接口或安装入口。确需结构改造时仍按单独授权的结构变更流程执行。

## 四、发布验证

发布前已运行：

```text
node --test scripts/tests/skill-frontmatter.test.mjs scripts/tests/release.test.mjs
node scripts/verify-skill-repo.mjs

```

结果：10/10 Node 测试通过，Skill 仓库验证通过，空白检查通过。新增评估场景需要在支持 Skills 的客户端中进行人工 forward-test。

## 五、安装与使用

```bash
npx skills add https://github.com/canglei9527/ai-maintenance-skills
```

已安装旧版本的使用者需要重新同步或重新安装 Skill，才能获得 v0.4.8 的执行收敛和局部诊断规则。
